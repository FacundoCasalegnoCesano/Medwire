# Investigación de UI: 21st.dev

**Fecha:** 2026-11-03\
**Alcance:** revisión manual y de solo lectura de 21st.dev, páginas de componentes, documentación, condiciones y páginas de precio. Se inspeccionó catálogo por categorías y se verificó código de uso, dependencias y licencia en una muestra de componentes pertinentes para Mendwire. No se instaló nada ni se accedió a contenido tras pago. Los enlaces de cada ficha son demos en vivo; los snippets de uso y metadatos (incluidos License/Dependencies cuando aparecen) son evidencia pública de la ficha. El contenido íntegro de `Component.tsx` puede requerir cuenta y consume cuota de copias.

## Qué es hoy 21st.dev

No es solo una galería de inspiración: es un marketplace/registro de componentes para React y Next.js, además de herramientas MCP/CLI, generación de UI (“21st AI”), revisión visual de PRs (“Design Bug Bot”), temas, plantillas, shaders, iconos y apps comunitarias. La portada y el catálogo público muestran más de 12.000 componentes, ~350 plantillas, ~950 temas y 138 apps; estos conteos cambian con el tiempo. Componentes son piezas React/TypeScript con Tailwind y convención shadcn registry; muchas páginas exponen demo viva, snippet `Usage.tsx`, metadatos de autor, fuente, dependencias y licencia.

Categorías visibles del catálogo principal: héroes, shaders, fondos, features, pricing, testimonials, AI chats, botones, cards/grids, sign-in, navegación, footers, dashboards, texto, CTAs, galerías, formularios y clientes. La agrupación de dashboards y colecciones temáticas descompone shells, sidebars, tablas, charts, estados vacíos y cards; sirve para investigar patrones separados, no como un kit uniforme.

### Gratis, cuotas y licencias

- La cuota de 2 copias/instalaciones al día es para el botón de copy/install de 21st con cuenta free; el browsing, búsqueda y preview son abiertos. Esa cuota **no** limita la fuente pública del autor. Por ejemplo, el registry oficial de Magic UI se puede abrir directamente y obtener sin pagar ni autenticarse, bajo la licencia MIT original. Si la fuente solo está en el panel de código 21st, las fichas explican que ese source se copia con cuenta gratis y computa hacia las 2 copias diarias. Builder elimina el límite del marketplace, pero no hace falta para investigar.
- 21st AI requiere plan con créditos; la fuente oficial presenta Builder + AI desde US$15/mes facturado anual, credits mensuales y top-ups. No hace falta usar AI para copiar componentes publicados. Plantillas vendidas por autor tienen compra aparte; no confundir su precio con los componentes.
- **MIT del sitio/plataforma no cubre todo el catálogo.** La licencia es por ficha y debe comprobarse. Algunas fichas publican MIT; otras no muestran licencia, por lo que acá figuran como **no verificada**. La licencia MIT permite uso, modificación y distribución con sus condiciones, y conserva copyright/aviso de licencia.
- Los términos prohíben reutilizar demos, screenshots, videos, GIFs y metadata de 21st; obtener código no concede derechos sobre esos materiales. También prohíben redistribuir el componente en otros medios sin enlace claro y visible a su ficha original. Respetar licencia upstream y atribuir al autor si el componente deriva de OSS. No se debe copiar media/demo como diseño final ni presentar trabajo comunitario como propio.
- La fuente registry puede ser la fuente del autor (por ejemplo `.../r/foo.json`) y no siempre un archivo GitHub. El directorio de código público puede mostrar el snippet del demo sin mostrar componente completo. La licencia no inferida permanece “no verificada”.

## Candidatos útiles y referencias futuras

Cuatro componentes tienen código fuente accesible sin cuenta en el registry del autor, demo y licencia rastreable: Terminal de Magic UI, Code Block de @iconiq y Auth Form de SmoothUI. Terminal Typewriter también cumple esos criterios y queda como alternativa a la terminal de Magic UI. La cuota de 2 copias diarias aplica al flujo de copiar/instalar de 21st, no a esos registries públicos. No hace falta suscripción para sus archivos originales; respetar la MIT y la atribución indicada.

1. **Code Block — @iconiq**: primera opción visual para una ventana de archivo en landing o ejemplo ilustrativo. El registry original incluye `code-block.tsx`; la ficha muestra MIT, `motion` y `lucide-react`. Demo clara con pestaña de `greet.ts`, líneas y copy; integrar como archivo de componente y ajustar tokens hacia el workbench oscuro. Reducir el movimiento del copy si no aporta.
2. **Terminal — Magic UI**: fuente `registry/magicui/terminal.tsx` accesible y MIT del repo original. Buena para una secuencia técnica ilustrativa. Reemplazar los comandos de instalación y la falsa confirmación de éxito por contenido veraz de Mendwire; mostrar resultado estático con reduced motion. Es el mejor componente fuente, no un shell completo de IDE.
3. **Auth Form — SmoothUI**: fuente `auth-form.tsx` pública, MIT, deps `motion` y `lucide-react`. Puede aportar forma y feedback al login/registro, pero su demo es presentation-only: simula success con timeout y ofrece login por enlace/proveedor. Adaptar handlers, estados, copy y navegación a la auth existente; no reutilizar esos estados falsos.
4. **Terminal Typewriter — Beste**: fuente `terminal1` pública, MIT, deps `clsx`, `tailwind-merge` y `lucide-react`. Alternativa auténtica a Terminal si se prefiere el patrón de varias órdenes. Tiene más configuración y animación; escoger solo una terminal y convertirla en salida estática en reduced motion.

**Solo inspiración o futuro, no candidatos de implementación actual:** Auth Forms de Layro System (licencia/fuente upstream por confirmar); Sign In Form de Ruixen (licencia por confirmar, providers que Mendwire no ofrece); Pasta UI Code Block (fuente upstream no comprobada, varias deps); Data Grid Table (MIT y fuente ReUI, pero demasiado funcional para una lista pequeña); Sidebars (MIT y fuentes visibles, pero sus layouts y secciones demo no reflejan el menú actual); EmptyState (licencia no verificada). **AI Diff**, **Uptime Card** y **API Key Manager** representan acciones o datos que Mendwire aún no tiene. **Aurora Background** y **Glass Code Block** son adornos de mayor peso y menor encaje con el diseño aprobado; no seleccionarlos como finalistas.
## Costos y compatibilidad a comprobar al adoptar

- Tailwind 4 está en el repo; revisar que clases de una ficha usen utilidades compatibles y no asumir configuración v3 (especialmente plugins, `@theme`, `tailwind.config`). Componentes pueden importar shadcn locales no incluidos en la ficha resumida; las dependencias de cada snippet no son una lista garantizada de todos los archivos necesarios.
- Next.js 16/React 19: código con estado/DOM/animación necesitará client boundary (`"use client"`). Evitar transformar toda la página a client por un adorno pequeño.
- Motion: respetar `prefers-reduced-motion`, detener loops, evitar auto typing que retrase lectura. Animar solo una señal puntual o mostrar resultado estático.
- Fondos/shaders/WebGL: aumentan consumo GPU/batería y pueden fallar en móviles, navegadores con WebGL bloqueado o pestaña en segundo plano. Mantener contraste, fallback estático y acotar al hero; nunca hacer overlay opaco que tape la composición.
- Tablas: en móvil priorizar vista adaptable con scroll horizontal controlado o filas compactas; mostrar foco y nombres de acción; no ocultar fuentes/errores. Accesibilidad de tabla/chart no queda demostrada por un screenshot de demo.
- Revisar copy y estados contra `PRODUCT.md`: `READY` solo significa fuentes listas; no meter uptime, analysis, impact, AI, repair, scheduled scan ni GitHub write.

## Inspección visual directa

Se inspeccionaron en el navegador las fichas **Terminal — Magic UI** y **Code Block — @iconiq**. Ambas muestran una tarjeta/panel claro sobre el fondo negro de la propia página 21st, y un botón “Preview” que lleva a demo individual. Terminal es una ventana CLI con semáforo, output verde y tipeo; Code Block es una ventana de archivo con pestaña `greet.ts`, números, syntax colors, línea activa y botón Copy. El panel de la demo es blanco, no hereda el workbench oscuro de Mendwire. Esto comprueba que el catálogo sí contiene piezas técnicas originales, aunque adaptarlas al navy de Mendwire sigue requiriendo integración visual propia.

No se guardaron capturas locales: el runtime Playwright existente no pudo iniciar Edge incluso con `TEMP`/`TMP` apuntando a un directorio escribible; la inspección visual sí se completó mediante el navegador in-app del entorno. No se intentó login, descarga ni bypass de cuota.

Para **Terminal**, la ficha 21st da opción de copy dentro de la cuota del marketplace, y además vincula `magicui.design/r/terminal`; el JSON del registry oficial Magic UI es público e incluye el archivo `registry/magicui/terminal.tsx`, imports desde `motion/react` y util `cn` local. La ficha enlaza la licencia MIT del repo Magic UI. Este es código real editable del componente original y puede obtenerse directamente de Magic UI sin consumir cuota de 21st; no es una reconstrucción por prompt. Para **Code Block**, el endpoint del registry es ahora confirmado públicamente: `name: code-block`, archivo `code-block.tsx` con contenido de 14.996 caracteres, deps `motion` y `lucide-react`; la ficha declara MIT. Para **Auth Form**, el registry `smoothui.dev/r/auth-form.json` contiene `auth-form.tsx` (18.774 caracteres) y sus deps; la ficha enlaza MIT. Para **Terminal Typewriter**, `ui.beste.co/r/terminal1.json` contiene fuente de 14.838 caracteres, deps `clsx`, `tailwind-merge`, `lucide-react`; la ficha declara MIT. Estos cuatro registries no requieren login ni consumen cuota de 21st.
