# Cult UI y Animata: investigación para el rediseño de Mendwire

Fecha de consulta: 3 de noviembre de 2026. Alcance: catálogo público, licencias, páginas de componentes, demostraciones visibles, instrucciones de instalación y código accesible públicamente. No se instaló nada, no se modificó la aplicación y no se probó el código dentro del repositorio.

## Recomendación ejecutiva

La nueva dirección debe reorganizar las páginas para que Mendwire se entienda como una herramienta de ingeniería de software. Cambiar solamente el fondo deja la misma jerarquía de landing y el mismo producto visual. Conviene establecer un sistema consistente en el encabezado público, acceso y workspace: navegación persistente, superficies de editor y consola para ejemplos, contenido denso ordenado como una aplicación técnica y estados legibles como texto.

Cult UI encaja mejor en los detalles de programación porque ofrece **Code Block**, **Terminal Animation**, **File Icons**, controles con estado y tabs. Animata aporta piezas pequeñas y copiables para carga, navegación y movimiento, pero la mayoría de su catálogo son demostraciones de animación genéricas. Las dos bibliotecas deben servir como fuentes de piezas adaptadas, no como sistemas visuales completos. Las capturas consultadas muestran que cada sitio también impone una estética de demostración que no hace falta trasladar.

Propuesta por superficie:

- **Landing:** cabecera compacta con marca y navegación real; titular corto; a su lado, un ejemplo de producto enmarcado como editor/API workspace, con pestañas de contrato y repositorio, fragmento OpenAPI/TypeScript y resultado de validación de fuentes. Etiquetar ese flujo como ilustrativo y dejar visible que “Sources ready” solo significa que las fuentes pasaron una comprobación. Evitar un panel que aparezca oculto por hover y fondos animados como protagonista. Mantener un único detalle decorativo discreto, si hace falta.
- **Acceso:** conservar una estructura directa de producto, con el mismo encabezado, reglas, tipografía, campos y foco del workspace. Acompañar el formulario con una columna de contexto técnico breve y estática; no repetir el hero de marketing ni poner el acceso dentro de una falsa ventana de código.
- **Workspace:** tratarlo como aplicación desde el primer vistazo: barra superior con marca, ubicación y cuenta; navegación lateral persistente en escritorio y navegación accesible compacta en móvil; área principal con encabezado, acción primaria y lista/tabla de monitores; vista de detalle que agrupe contrato, repositorio, fecha de chequeo y errores junto al estado guardado. Mantener ambas fuentes y los errores visibles; el detalle no debe depender de hover ni de un efecto que tape el contenido.
- **Lenguaje común:** acordar una sola paleta, tipografías, escala de bordes y espaciado antes de agregar efectos. La marca de tres barras permanece. Monospace se reserva para rutas, URLs, código, comandos y etiquetas cortas. Un solo estilo de movimiento para cambios de estado; respetar `prefers-reduced-motion`. Usar los colores de estado junto con texto y, cuando corresponda, icono.

La identidad puede revisarse según autorización del usuario, pero `PRODUCT.md` mantiene compromisos concretos: marca Mendwire, separación entre contenido público y workspace privado, estados veraces, teclado, foco, móvil y movimiento reducido. La estética de IDE no debe sugerir que hoy existen análisis de código, IA, hallazgos, ejecuciones programadas ni propuestas de reparación.

## Licencias y qué queda fuera

### Cult UI

El repositorio oficial publica [LICENSE.md, MIT](https://github.com/nolly-studio/cult-ui/blob/main/LICENSE.md), y la página oficial ofrece la biblioteca de componentes bajo MIT. En sus términos, Cult UI confirma que **58 componentes que antes pertenecían a Cult Pro** se publicaron bajo MIT; la oferta pagada retirada conserva sus bloques y plantillas bajo términos propios. Ver [Cult UI](https://www.cult-ui.com/), [README del repo](https://github.com/nolly-studio/cult-ui/blob/main/README.md) y [términos de Cult Pro](https://www.pro.cult-ui.com/terms).

**Límite de licencia:** los componentes publicados en la biblioteca pública y amparados por ese repo se pueden copiar y modificar conforme a MIT, conservando el aviso/licencia al distribuir las partes correspondientes. No trasladar a esta autorización los bloques, plantillas, descargas de compradores, contenido de AI SDK Agents ni servicios externos. **AI SDK Agents** está marcado como pagado y se aloja en otro producto; no se necesita para añadir componentes de Cult UI. `Cult UI Pro` está retirado, pero sus bloques/plantillas no se volvieron MIT. No encontré motivo para usar premium ni para acceder a material restringido.

### Animata

El repo oficial contiene [LICENSE.md, MIT](https://github.com/codse/animata/blob/main/LICENSE.md), con permiso expreso de uso, modificación y distribución sujeto a conservar los avisos requeridos. La web declara que sus componentes son gratis/open source. La ficha de cada pieza publica vista previa, instalación y código manual/registry. Esto aplica al código del componente del repo; revisar por separado atribuciones de cualquier imagen, marca, icono o recurso de terceros que se agregue.

Las secciones **Demos** son páginas de ejemplo y **no** evidencia para reutilizar material de producto de terceros. Las piezas candidatas de abajo remiten a documentación de componentes y/o registry de código. No se identificó una colección Pro que haga falta para este rediseño.

## Compatibilidad con Mendwire

El checkout usa Next.js 16.4.2, React 19.3.1, Tailwind CSS 4.3.3 y Motion 14.9.0; también ya tiene `clsx`, `tailwind-merge`, `lucide-react`, `components.json` y `cn`. Cult UI declara Tailwind CSS v4, tokens shadcn y Motion en gran parte de la biblioteca; Animata se copia a la app y su guía actual incluye Tailwind v4 y Motion opcional. Esto da una buena base de compatibilidad, pero **no equivale a compilar cada pieza contra Mendwire**.

Cult UI requiere parte del andamiaje de shadcn (`components.json`, alias, `cn` y variables de tema). Mendwire ya tiene el alias/utilidad/configuración base, aunque su CSS usa tokens propios (`--surface`, `--foreground`, etc.), no los tokens shadcn que muchos componentes esperan (`--background`, `--card`, `--muted`, `--ring`, etc.). Copiar y pegar exige mapear tokens a la paleta Mendwire y revisar las dependencias concretas que cada ficha enumera. El registry puede instalar las dependencias declaradas, pero aquí no se ejecutó la instalación. Ver [instalación Cult UI](https://www.cult-ui.com/docs/installation), [temas Cult UI](https://www.cult-ui.com/docs/theming) y [setup de Animata](https://animata.design/docs/setup).

| Biblioteca | Next/React/Tailwind | Dependencias y fricción local |
|---|---|---|
| Cult UI | Se dirige a React + Tailwind v4 y tiene guía para Next.js App Router. Motion y React ya están presentes en Mendwire. React 19.3.1 es plausible, aunque no se verificó cada componente en ese runtime. | Importación por shadcn registry; `cn`/alias existen. Habrá que adaptar variables de tema y revisar módulos específicos: algunas piezas agregan Base UI, Sonner, Prism u otras dependencias. No usar sus estilos globales ni reemplazar el sistema de tokens en bloque. |
| Animata | El sitio indica React/Tailwind y el setup reciente está preparado para Tailwind v4. El código de ejemplos usa APIs estándar de React; `Fluid Tabs` importa `use` de React y por tanto requiere React 19. | No instala runtime de Animata: copia archivos fuente. El registry de `Code` declara `lucide-react@^0.475.0` y el de `Fluid Tabs`, `lucide-react@^0.475.0` + `motion@^12.38.0`; el repo ya tiene `lucide-react@1.67.0` y `motion@14.9.0`, fuera de esos rangos declarados. No ejecutar el CLI a ciegas: inspeccionar imports y referencias, conservar las versiones actuales si el código copiado es compatible y ajustar rutas `@/lib/utils`/`@/hooks` y tokens (`bg-background`, `border-border`) al proyecto. `Grid` no declara dependencias externas. |

## Orden de preferencia

Para construir un lenguaje de producto coherente, empezaría por una maqueta estructural de las tres superficies descritas arriba y aplicaría solo estos patrones en ese orden: **Cult Code Block** para el ejemplo de código público; estructura propia y estática de lista/detalle para monitores; **Cult File Icons** en datos con formato claro; **Cult Halo Badge** solo en modo estático y con estado textual. Después evaluaría **Animata Code skeleton** para cargas reales y **Fluid Tabs** o tabs simples para alternar contenido. **Terminal Animation** queda exclusiva para una demostración claramente ilustrativa. No tomaría el fondo, la tarjeta brillante de CI ni efectos de hover como fundamento de navegación o de la identidad completa.

No recomiendo adoptar el set `Halo` entero: el lenguaje de frosted glass, rim luminoso, springs y Base UI aumenta diferencias de superficie y dependencias y choca con un workbench legible. Tampoco usaría el catálogo de Animata para armar una mezcla de efectos. Primero se define la estructura de aplicación, luego se elige una o dos interacciones que expliquen algo real.
