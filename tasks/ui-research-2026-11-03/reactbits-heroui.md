# Investigación de React Bits y HeroUI para Mendwire

Fecha de consulta: 3 de noviembre de 2026. Revisión documental de páginas oficiales, catálogos, licencias y compatibilidad; inspección visual/AX de páginas públicas con navegador in-app. No se instalaron paquetes ni se modificó la aplicación.

## Hallazgo principal

Las dos bibliotecas resuelven trabajos distintos. HeroUI OSS ofrece primitives de producto con comportamiento y accesibilidad integrados; React Bits gratuito ofrece piezas expresivas y efectos visuales, no una arquitectura para todas las pantallas. Para Mendwire, una dirección visual original puede usar HeroUI como caja de herramientas para controles y comportamiento, con CSS/tokens propios, y seleccionar React Bits solo donde una interacción aporte información o personalidad. No conviene adoptar el look de los demos como identidad completa.

El producto local actual ya usa Next.js 16.4.2, React 19.3.1, Tailwind 4.3.3, Motion 14.9.0 y componentes instalados por registry shadcn (Magic UI/KokonutUI). La app actual cubre registro/acceso y un workspace privado para CRUD de monitores OpenAPI/Git, con validación de fuentes; no tiene análisis de código, monitorización programada, propuestas ni PR. La interfaz debe conservar los estados reales y los límites del producto aunque la identidad visual se vuelva a decidir. Esta distinción sigue la evidencia descrita en `PRODUCT.md`; `DESIGN.md` es una propuesta visual local previa, no un mandato para esta investigación.

### React Bits Pro: separar preview, producto free y pago

- La página de [Portfolio](https://pro.reactbits.dev/docs/templates/portfolio-template) dice literalmente que el template es gratis para uso personal/comercial. No pide licencia en la descripción de uso. Sin embargo, la página pública consultada no expuso botón o enlace de descarga/source usable; el acceso real a descargarlo no quedó confirmado. La plantilla incluye Next.js 16+, React, TS, Tailwind 4, Motion, WebGL, Lenis, Matter.js y next-themes; por cantidad de dependencias y estilo de portfolio no parece una base mínima para el workspace.
- La página de [Terminal Dark](https://pro.reactbits.dev/docs/agent-kit/skills/terminal-dark) dice “Free, no licence required” en el encabezado, pero luego indica que está licenciada bajo el acuerdo React Bits Pro y que no se puede redistribuir su texto. Esa ambigüedad interna significa que no se debe tratar como fuente libre inequívoca ni copiar su skill sin aclaración del titular.
- El resto de los previews de Pro, aunque muestren nombres como `Data Table`, `App Shell`, `Monitoring`, `Dashboard`, `Authentication` o `Sidebar`, se clasifican en los planes pagos en la página actual. El acuerdo de React Bits Pro prohíbe copiar/extraer/replicar fuente e implementación basándose en demos públicos. Esta investigación no usó las previews de pago como especificación ni inspeccionó su código.

## HeroUI OSS v3: base gratuita y shortlist

HeroUI v3 fue reescrito; no se debe leer documentación v2 como si fuera el API actual. La guía oficial pide React 19+ y Tailwind CSS 4; el repositorio dice Apache-2.0. La instalación recomendada es `npm i @heroui/styles @heroui/react`, más `@import "tailwindcss";` seguido por `@import "@heroui/styles";`. No requiere `HeroUIProvider`. Usa componentes compuestos, CSS BEM/variables y estilos globales separados. El repo de Mendwire ya cumple versiones, pero todavía no tiene esos dos paquetes ni el CSS de HeroUI. Añadir ambos afecta el estilo base y debe probarse con tokens/estilos actuales; no se estimó el tamaño del bundle. [Quick Start oficial](https://heroui.com/en/docs/react/getting-started/quick-start), [migración v2→v3](https://heroui.com/en/docs/react/migration), [repo v3/LICENSE Apache-2.0](https://github.com/heroui-inc/heroui/blob/v3/LICENSE).

La base OSS incluye Button, Alert, Form, TextField, Input, TextArea, FieldError, Select, ListBox, Dropdown, Modal, Drawer, Sheet, Table, Tabs, Toast, Tooltip, Skeleton, Pagination, Chip, Badge, Breadcrumbs, Accordion, Calendar y controles adicionales. Componentes destacados en el showcase `Pro` no pasan a ser gratis por tener preview; hay que distinguir la etiqueta de versión OSS y `heroui.pro`.

| Pieza y fuente | Aplicación posible | Paquete, accesibilidad, móvil y límite |
|---|---|---|
| [Button](https://heroui.com/en/docs/react/components/button) · source y style source disponibles desde la página | Acciones consistentes: guardar, crear, retirar, volver a activar. | Import `@heroui/react`; el componente documenta disabled/pending, variantes, foco y icon-only. ## Qué sistema UI tiene sentido evaluar

**HeroUI OSS v3 es la base gratuita más coherente si se prioriza un sistema consistente de comportamiento/accessibility; React Bits free aporta acentos originales a demanda.** HeroUI ya encaja en las versiones de runtime actuales y su API cubre los controles reales de Mendwire. Para preservar una identidad propia no hace falta conservar sus valores visuales por defecto: el repo declara theme CSS-first y clases personalizables. De todos modos, introducir el paquete de estilos, ajustar colores/tipografía/radius/estados y armonizar estilos con Tailwind requiere una prueba visual real antes de decidir adopción global.

React Bits se evalúa mejor pieza por pieza: libre de coste de licencia para el catálogo abierto, código local configurable, pero la licencia MIT+Commons Clause restringe redistribución como kit. No es un framework de design system y no debe controlar el tono de todos los formularios/listas. Sus elementos más razonables son los que cambian foco o lectura sin añadir claims del producto: Spotlight Card (con intensidad baja), Animated List (si la navegación se valida en lista) o una pieza micro para un estado con texto. `Code Slots` y `Stepper` requieren una razón de producto; `Status Mark`, fondos perpetuos y Agent-themed widgets pueden insinuar análisis o automatización no implementados.

La idea de una estética IDE/programación no requiere imitar un template. Se puede derivar de jerarquía de información (rutas, fuente, estado, acciones), reglas de borde, tipografía técnica en datos, densidad elegida por el usuario y espacios de lectura claros. Elegir contraste, paleta, movimiento y forma de los módulos queda pendiente de dirección visual; `DESIGN.md` sirve para comparar la propuesta anterior, no para cerrar esa decisión.

## Inspección y límites

- React Bits: inspección visual/AX de `Spotlight Card`; la página muestra preview oscura, panel lateral por categoría, pestañas Preview/Code, controles de color/intensidad/shape y campos para viewport Desktop/Tablet/Mobile. Se abrió Code y se comprobó que su source visible tiene fallback por `prefers-reduced-motion` y activación con foco. Observación de una página pública, no auditoría del repo completo ni medición de rendimiento.
- HeroUI: inspección visual/AX de [Table](https://heroui.com/en/docs/react/components/table), versión docs `v3.2.7`; ejemplo con datos, selección, orden, paginación y resize; la primera visita muestra un popup promocional HeroUI Pro sobre la parte inferior izquierda. No indica que Table sea de pago: está en la navegación OSS y tiene enlace a source/estilos.
- No se descargaron templates o assets remotos, no se accedió a login, no se intentó recuperar source protegido, no se instaló paquete, no se inspeccionó el runtime de Mendwire, no se probó lector de pantalla real ni se hizo benchmark CPU/GPU o device móvil. Las screenshots aparecieron en la inspección in-app, pero no se guardaron como PNG; no presentarlas como artefactos locales.
- Las páginas Pro pueden cambiar tanto en precios como en acceso y conteos. La etiqueta “Free” comprobada en el template Portfolio describe permiso de uso, pero el acceso efectivo al archivo de source no se pudo confirmar.
