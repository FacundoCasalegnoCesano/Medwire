# Mendwire

Mendwire gives each client access to an individual workspace with its own navigation and account management. People can register and sign in immediately, without mandatory email verification, and can log out, request a password reset, and use a one-time reset link. Clients can create, edit, list, and withdraw private Monitors, and check public OpenAPI and Git sources before they are marked ready. Ready monitors support durable scheduled and manual OpenAPI checks, saved baselines, breaking-change findings, private run history, and queued impact analysis for breaking findings. Initial impact coverage is limited to public GitHub JavaScript/TypeScript `fetch` and Axios usage; the panel shows commit-bound evidence, candidates, and coverage limits. See [`tasks/monitors-verification.md`](tasks/monitors-verification.md) for monitor CRUD and source validation, [`tasks/monitoring-verification.md`](tasks/monitoring-verification.md) for check operations, and [`tasks/plan.md`](tasks/plan.md) and [`tasks/todo.md`](tasks/todo.md) for the product roadmap. The 3.2 verification record distinguishes real GitHub worker runs from controlled analyzer evidence fixtures. Repair proposals and repository publication remain roadmap work. See [`tasks/impact-analysis-verification.md`](tasks/impact-analysis-verification.md) for scope and QA evidence.

## Email

For now, password reset email is tested by capturing the message inside the test process; integration tests do not connect to an SMTP server. The local app has no email service configured. A real SMTP provider can be configured later with the `SMTP_*` settings in `.env` when email delivery is needed.

## Local setup

Use Node.js 24 or newer (Node 26.4.0 is installed in the current environment). Install PostgreSQL locally with its listener bound to loopback on port `5432`, and start the service. Copy `.env.example` to `.env` and set a private `BETTER_AUTH_SECRET` with at least 32 characters. Create `.env.postgres.local` with `POSTGRES_ADMIN_PASSWORD=` and enter the local PostgreSQL administrator password on that line; keep it out of chat and source control. Install dependencies with `npm install`, then run `./scripts/setup-local-postgres.ps1` in PowerShell. It creates dedicated `mendwire` and `mendwire_test` databases and an application role, stores their generated connection URLs in ignored local environment files, clears the administrator password from `.env.postgres.local`, and applies the current migrations. It stops if a `mendwire` role or either database already exists.

The setup script sets `DATABASE_URL` and `AUTH_TEST_DATABASE_URL` for the local app database and the dedicated `mendwire_test` database. Run `npm run db:generate`, then `npm run db:migrate` after checking that `DATABASE_URL` points to the intended local database. Use `npm run install:oasdiff` to download the pinned oasdiff 1.35.0 binary with SHA-256 verification, or set `OASDIFF_PATH` to an audited binary with that version. The downloaded binary is stored under ignored `.tools/`.

Run the app and the monitoring worker in separate PowerShell terminals. The app binds to `127.0.0.1:3000` with `npm run dev`; the worker runs with `npm run worker:monitoring` and loads `.env`. Both require `DATABASE_URL` for the same local database. Checks continue without an open browser while the worker is running. Run `npm run lint`, `npm run typecheck`, `npm test`, and `npm run build` for project checks. Run `./scripts/test-auth-integration.ps1` to load local database URLs and execute the integration suite against `mendwire_test`; the integration tests refuse non-loopback databases whose name does not end in `_test`.

Use `npm run preview` to review the compiled app in production mode. It builds once when the command starts and then serves that build, so navigating between routes does not compile each route in development mode. After changing source files, stop the preview and run the command again to build the changes. Use `npm run dev` when actively editing and you need hot reload.

Beta access is read from the workspace's server-side `entitlementState`; request bodies cannot set a plan. Current beta defaults are three active monitors, checks every 24 hours, and a 300-second manual-check cooldown. Usage ledgers and monthly analysis/proposal enforcement belong to later work.

No production email provider or deployment settings are configured, and no production credentials are stored in this project.
